## Syntax highlighting

Themes (`markdown.shikiConfig.themes` in `astro.config.mjs`): `github-light-default` (light), `github-dark-default` (dark).
The old `github-light` / `github-dark` pair fails AA (orange `#e36209` on white 3.49; comments `#6a737d` on `#24292e` 3.05).

| Theme | Background | Min token ratio (samples) | Required |
|---|---|---|---|
| github-light-default | `#ffffff` | 4.55 (comments, `#6e7781`) | 4.5 |
| github-dark-default | `#0d1117` | 6.15 (comments, `#8b949e`) | 4.5 |

The painted background is the Shiki one (`--shiki-light-bg` / `--shiki-dark-bg`, used by `.astro-code` in `global.css`).
`node scripts/check-contrast.mjs` (exit 1 on any token below 4.5:1) does two checks, skipped with `--markdown`:

- Always, no build: reads the theme names from `astro.config.mjs`, tokenizes samples in ts, bash, python, c, json, diff and yaml
  with `shiki`, and checks every non-whitespace token. Limit: only token kinds present in the samples are tested; add samples when
  posts use other languages.
- Automatically when `dist/shiki.css` exists: checks every `--shiki-light` / `--shiki-dark` value against the `-bg` values.
